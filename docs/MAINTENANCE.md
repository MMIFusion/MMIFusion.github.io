## 文章

初始来源：`261028-多模态信息融合.xlsx`（本机现名 `261028.xlsx`），工作表「微信文章导出」，第 2–240 行，共 239 条。2026-11-12 合并「壹伴-图文分析导出-多模态信息融合.xlsx」Sheet1 第 3–27 行：新增 22 篇、合并更新 2 篇、按用户确认剔除第 22 行统计错误，共 261 篇。

旧格式的 `import_articles.py` 读取 B 标题、C 发布时间、F 微信链接。两格式合并使用 `scripts/merge_articles.py`：壹伴标题在 A 列，链接必须从 A 单元格的 hyperlink relationship 读取，不能从显示文字猜测。新表 C/D/E 为日期/小时/分钟。每篇保存 `sourceFile`、`sourceSheet`、`sourceRow`；发布日期不是论文发表日期。完整原始字段保存在本机合并工作簿的两张来源表，不发布到网站。

分类与主题由 `scripts/import_articles.py` 中规则辅助生成；可以修正规则后重导入，或直接修改 `data/articles.json`。重新导入会覆盖直接编辑，长期修正应改规则或为导入流程增设人工覆盖文件。会议期刊字段只从文章标题提取，不代表独立核验了录用状态。

优先以规范化微信链接去重。新表使用短链接、旧表使用参数链接时，只有“同一公众号、完整标题、发布日期、图文位置”唯一跨格式匹配才合并；不能仅按标题去重，也不能合并两个不同的参数文章标识。本次两条匹配的新短链接作为 `urlAliases` 保留，原 URL 和 ID 不变；重复文章的四项统计全部由新表覆盖，不求和。合并表的发布时间同样采用新表，完整旧记录保留在来源表中。微信验证页阻止了短链接在线解析，因此本次跨格式匹配依据上述表内字段。

## 站点设置

`data/site.json` 保存公众号链接、数据资源站内入口、交流微信、维护者与主站域名。不要填写未经确认的账号、二维码或邮箱。

## 扩展栏目

编辑 `data/portal.json`。每个条目使用稳定唯一的 `id`，保留 `source` 官方链接。`verifiedAt` 记录最近一次整体核对日期；批量更新前应逐项核实来源，不要只改日期。

- `conferences`：当前收录 2027 年图像融合及多模态研究相关的 8 场 CCF A 类会议。每场会议包含 `events`、地点 `location` 和可选的待公布说明 `pending`；没有已公布日期时 `events` 必须为空，不放占位日期。精确截止节点使用 `kind: deadline` 和带 UTC 偏移的 ISO `at`。AoE 用 `-12:00`，不能误写成 UTC。只公布日期时用 `kind: date`、`start` 和不包含在事件中的 `endExclusive`。例如 8 月 2–4 日的结束值为 8 月 5 日。`original` 保留原始日期 / 时区说明。事件可有自己的 `source`，否则继承会议来源。构建自动生成已确认节点的单条及全部 `.ics`，不安排自动更新订阅。
- `teams`：一人一卡，`name`、`lead` 与单元素 `members` 必须对应同一人；每人使用自己的简介与链接。前四位固定为马佳义、刘日升、吴小俊、刘羽，其余综合学术资历、研究关联与同校归组整理。`note` 和 `links` 展开显示，`verification` 区分核对来源。`aliases` 兼容旧资料检索，`cities` 支持跨地区筛选。`relatedQuery` 检索公众号文章，`opportunity` 关联既有招募条目。来源与编辑规则见 [团队目录维护说明](TEAMS.md)。
- `opportunities`：`teamId` 关联团队、`types` 表示招募类别。长期招募必须有官方原文依据；限期招生请写明到期时间并及时更新 / 移除。当前 `expires` 为记录字段，不自动下架。
- `venues`：将官方 `scope` 与本站整理的 `fit` 建议分开。`ccf`、`ccfPage`、`ccfArea` 对应所参考目录，未收录条目使用 `未收录` 和空页码；数组按 A、B、C、未收录排列，同级为编辑组织顺序。`guide` 可为空，并用 `guideNote` 说明待公布；旧届指南必须用 `guideLabel` 明示年份。`aliases` 用于简称检索；`articleVenue` 若非空必须匹配现有文章分类，否则使用 `relatedQuery` 检索。`calendar` 可关联会议 ID。未核实的信息不填影响因子或录用率。分类与来源记录见 [投稿目录核对说明](VENUES.md)。
- `datasets`：首页精选入口；`catalog` 使用 `datasets.html#dataset=条目ID`，链接站内完整档案。完整目录的维护见 [数据目录说明](DATASETS.md)。本站仅保存说明与示例图，不托管数据集本体。
- `metrics`：定义、公式、注意点；若改计算约定，须同步浏览器 `assets/metrics-core.js`、Python 下载脚本与分析样例测试。

`data/community.json` 保存两类色板：`basicPalettes` 为单色系的五级浅至深序列，字段为稳定 `id`、`name`、`note`、`colors`（HEX）；`palettes` 保留原有组合色板。页面先展示基础色系，再展示组合配色，使用同一套卡片。构建生成 SVG / JSON 下载：基础系列使用 `palette-basic-{id}`，原组合色板继续使用 `palette-1` 至 `palette-4`，避免旧链接失效。检查脚本验证基础系列亮度严格递减。框架 SVG 由 `scripts/portal.py` 生成，绘图与指标 Python 脚本直接在 `downloads/` 维护。

收藏仅存当前浏览器的 localStorage（键 `mmifusion-bookmarks-v1`），不跨设备同步。图片只在内存中计算，不上传、不持久保存。投稿表单只生成预览与 GitHub 链接，维护者在仓库 Issues 中审核后手动更新数据。

每张配色卡同时提供整组复制、SVG 和 JSON 下载；下载入口必须覆盖全部色板，构建检查会核对。下方单独展示框架图和绘图脚本，避免重复展示同一组配色。

官方来源旁的「反馈勘误」及全站页脚「反馈问题」会将来源链接与标题带入投稿表单；只填写输入框，不自动提交。生成草稿后焦点转到预览，手机端同时滚动到预览。

## 日程展示与交互回归

首页从已收录的全部日程中按时间选择最近三个未结束节点，每 30 秒及页面重新可见时更新；全部结束后明确显示空状态，不以过期节点填充。会议日历支持「只看未结束节点」、领域/已公布状态筛选、检索组合、URL 保留筛选，截止前 72 小时突出提示。尚有待公布节点的会议保留可见，避免把未公布误判为已结束。所有已公布日程各有稳定锚点，提醒链接可直达对应节点。

`assets/calendar-core.js` 区分精确截止和纯日期：精确截止按 ISO 时刻判断；纯日期不倒计时，只有在结束日期连 UTC−12 时区也已结束时才移入往期。这个保守边界仅用于界面归档，不生成或暗示官方截止时刻，也不改变 ICS 的全天编码。单元检查：`node scripts/test_calendar.cjs`。

`assets/app.js` 提供全站统一的 `MMIFusionUI.notify`，复制、转发等功能共享提示计时器。提示显示于当前弹窗或页面；弹窗关闭后归还页面，避免后续操作提示藏在已关闭的弹窗内。会议对比弹窗需保留标题关联、滚动锁定、Escape 关闭与焦点返回。

## 构建与发布

页面模板：`scripts/build.py`、`scripts/portal.py`；样式：`assets/style.css`、`assets/portal.css`；交互：`assets/app.js`、`assets/portal.js`；指标计算：`assets/metrics-core.js`。

构建输出 `dist/` 供本地预览，同时将生成的 HTML、robots.txt、sitemap.xml 和 `.nojekyll` 同步到仓库根目录，复用根目录的 `assets/` 与 `data/`。请修改源文件后重新构建，不要直接编辑生成页面。

构建为本站 JS / CSS 和字体预加载自动附加内容哈希版本参数；文件变更会生成新 URL，减少发布时新旧资源混用。新增文字后可在安装 `fonttools[woff]` 的环境运行 `python scripts/build_fonts.py`，补齐本地字体子集，再运行常规构建。该脚本同步 CSS 字体 URL 与预加载版本，避免重复下载；日常 CI 构建仍仅依赖 Python 标准库。字体原稿缓存在忽略的 `outputs/font-sources/`，保留字体许可证。

GitHub Pages 沿用 `main / (root)` 的分支发布；GitHub 自带发布流程会在推送后部署。`Check website content` 仅做一致性检查，不另行部署，避免两套发布流程相互覆盖。`dist/` 为本地构建产物，不提交到仓库。

检查命令：`python3 scripts/check.py`、`node scripts/test_metrics.cjs`。检查文章标识、微信 URL、文章完整性、所有站内文件/锚点、页面标题层级与外链安全属性，并验证 ICS 的 UTC / 日期编码、资源关联及指标解析样例。

更新内容后在浏览器检查受影响页面，至少查看手机和桌面宽度，验证搜索、分类、分页、收藏、日历下载、时区切换、图片计算与导出、会议期刊对比、投稿预览及外链目的地。

## 视觉主题与动效

`assets/experience.css` 定义当前深蓝 / 紫色视觉、完整字号调整与各宽度布局；`assets/experience.js` 处理融合主题切换、论文分类、滚动渐入、阅读进度和动效偏好。`scripts/design.py` 生成原创首屏和专题卡片；不要直接改构建后的 HTML。

正文通常为 16–18 px，论文标题为 18–20 px。手机表单输入保留至少 16 px；日期、来源等辅助信息一般不小于 13 px。少量纯装饰英文 / 概念图注使用更小字号，不用于承载论文标题或正文。避免恢复旧版的 8–12 px 正文样式。

动效采用原生 CSS / Web Animations，用户可暂停；系统要求减少动态效果时默认暂停，用户明确点击开启后可恢复。选择存于 `mmifusion-motion`，可跨页面沿用。滚动渐入只在元素进入视口时播放一次；内容不依赖动画完成才显示。保留无脚本浏览与键盘操作。

网页字体来自 Google Fonts 官方仓库的 Noto Sans SC 和 Space Grotesk，OFL 文本与字体一同放在 `assets/fonts/`。字体已按本站文本做 WOFF2 子集，日常构建无需依赖字体工具；新增汉字若未包含会使用系统字体回退。需要刷新字形时，安装 `fonttools[woff]` 并运行 `python scripts/build_fonts.py`，再重新构建网页。原字体缓存在忽略的 `outputs/font-sources/`。

首页数据集图来自原数据资源目录资料，原图保存在 `assets/datasets/`，只作资源预览。论文卡片封面和融合首屏为本站原创概念设计，不是论文模型图或真实融合结果。

所有文章列表共用 `scripts/build.py` 的统计面板和 `assets/article-stats.css`：悬停标题或键盘聚焦显示“阅读量 → 点赞量 → 推荐 → 收藏”，其中推荐对应原表在看数。仅展示有数据的项目，真实 0 正常显示；日期按每篇来源，星标收藏仍是本机标记。桌面浮层不改变列表行高，Escape 可关闭，手机通过“查看数据”按钮展开。标题始终直接跳转公众号。

首页四个精选阅读栏目共用 `scripts/cover_art.py` 与 `assets/reading-covers.css`。封面按文章 ID 保持固定的图形、配色与方法名称；已精选文章使用独立设计，其余条目按稳定 ID 选择主题图形。同一文章在不同栏目使用同一封面。阅读、点赞、转发数据直接取 `article-stats.json`，不计算或模拟新计数，并标明各篇统计日期。电脑悬停或键盘聚焦卡片时展示统计，触屏设备在封面进入可见区域后展示；离屏图形暂停动画，遵循全站动效开关。仅增加原创装饰图，不修改公众号标题、链接、数据或分类。

## 人气榜、访问统计与趣味互动

`scripts/community.py` 生成首页榜单、状态栏、广告合作与趣味日历；`assets/community.css` / `community.js` 管理样式和交互，`community-core.js` 只包含北京时间日期及确定性的日签规则。

- 榜单数据：`data/article-stats.json`。合并脚本同步更新文章和统计。旧表 J/K/N/O 对应阅读/点赞/在看/转发，新表 I/AC/AB/U 对应阅读次数/点赞/在看/分享次数；不用“阅读人数”替代“阅读次数”。237 篇保留 2026-10-28 快照，24 篇使用 2026-11-12 快照。每条记录带 `snapshotDate`，榜单卡片展示各篇统计日期。缺值不转成 0。按主指标、阅读数降序，再按 ID 升序取前 10。按用户后续要求，论文列表新增公众号收藏数：新表 AA 列有值的 24 篇直接采用原值，其余 237 篇为 `null`，界面略去缺失项；新表的历史停供说明仍保留在原始工作簿中。`favoritesAvailable` 表示有至少一条记录，`favoritesComplete` 表示是否全部覆盖。网站星标仍只存 `mmifusion-bookmarks-v1`，转发不回写公众号计数。
- 网站 PV：使用官方不蒜子脚本，仅在 `mmifusion.github.io` 运行；本地预览与隔离测试不计数。通过隐藏返回节点读取真实总值后做数字动画，超时显示 `—` 并提供不可用状态。不能以浏览器 localStorage 或随机数冒充全站访问量。上线验证会产生少量真实访问，旧站访问不能追溯补齐。
- 日期统一使用 `Asia/Shanghai`，每秒更新；跨北京时间午夜刷新今日标识。趣味日签由日期字符串确定，没有接入传统黄历，也不预测录用。改文案可编辑 `community-core.js`，不要改真实会议数据来配合趣味内容。
- 好运数与检查清单仅存本机（`mmifusion-luck-v1`、`mmifusion-submission-checks-v1`），好运按北京时间每日归零。动效遵循全站暂停与系统减少动态效果设置，键盘和关闭操作应保持可用。
- 验证：`node scripts/test_community.cjs` 检查跨年、午夜与闰年；浏览器检查导航跟随、四榜顺序、收藏同步、分享、日历翻月、好运领取与 QR 扫描。

状态栏使用深色背景与 16–18 px 文本，时钟 / 访问量为 29–35 px；窄屏通过分行保持字号。时钟只对变化的数字播放短动画，完整时间放在 time 的 aria-label 中，不逐秒朗读。状态栏光轨、呼吸光点、好运流光和悬停反馈均遵循全站动效暂停设置；暂停装饰动画不停止真实时钟更新。
